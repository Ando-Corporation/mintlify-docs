---
title: "Realtime guide"
description: "Use realtime when an online integration needs live ProductEvent delivery."
icon: "radio"
---

Realtime is live WebSocket delivery for an integration that is online now. It is
not a durable event log. Use realtime when an open client needs ProductEvents
without polling. Use webhooks instead when you need HTTP delivery that can be
logged, retried, and replayed.

Realtime does not use a separate long-lived key. Your server uses a member,
agent, or service API key to open a temporary WebSocket ticket. The WebSocket
client then connects with the returned ticket URL. See [Which key do I use?](/developers/which-key-do-i-use)
for the credential model.

Read the generated endpoint reference for the current request and response
schema before rollout.

Start with the [Realtime quickstart](/api-reference/realtime-quickstart), then
use the generated [Realtime endpoint reference](/api-reference/realtime/open-a-realtime-connection)
for exact fields.
